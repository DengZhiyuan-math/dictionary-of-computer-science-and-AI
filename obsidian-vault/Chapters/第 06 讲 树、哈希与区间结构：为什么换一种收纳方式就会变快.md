## 第 06 讲｜树、哈希与区间结构：为什么换一种收纳方式就会变快

领域：算法与数据结构 · 细讲

<a id="chapter-06-section-01"></a>

### 哈希冲突：链地址法与开放寻址【重点】

哈希表根据键计算存储位置，不同键可能落在同一个位置，这就是冲突。链地址法在这个位置保留一组候选，再比较真正的键。开放寻址则按规则继续探查其他槽位。装得太满时，探查和冲突会增加，因此常通过扩容、重新散列维持效率。哈希相同不意味着对象相同，也不意味着哈希函数坏了。它适合按账号、订单编号快速查找，但一般不能直接回答某个价格区间里的所有记录。

<a id="chapter-06-section-02"></a>

### AVL 与红黑树【认识】

普通二叉搜索树可能因为插入顺序很不利，退化成接近链表的形状。AVL 和红黑树通过维护平衡条件，并在必要时旋转局部结构，避免搜索路径变得过长。AVL 对高度平衡的要求更严格；红黑树用颜色规则实现较宽松的平衡。你不需要背旋转细节，只需知道它们保留有序关系，支持查找、插入和删除。哈希表擅长按键定位，平衡树还适合找前驱、后继与有序区间。

<a id="chapter-06-section-03"></a>

### Heap 与优先队列【重点】

堆只保证父子之间满足优先级关系，不保证整个数组已经有序。最小堆使最小元素容易取出，取出后只需修复受影响的局部结构。它适合任务调度、合并有序流、维护前若干大元素，也为 Dijkstra 提供高效的下一节点选择。优先队列是对外提供的行为接口，堆是一种实现。别把这个堆与程序内存中的堆区混淆：它们是同一个英文词在不同上下文中的用途。

<a id="chapter-06-section-04"></a>

### Union-Find，并查集【重点】

并查集维护哪些对象属于同一组，核心操作是找代表以及合并两组。路径压缩让沿途节点以后更快找到代表，按大小或秩合并避免形成特别高的树。例如一条条加入网络连线，询问两台机器是否已经连通，不必每次重新搜索整张图。它适合动态添加连接以及最小生成树中的环检测。基本并查集不擅长删除连接，也不能直接告诉你两点之间具体该走哪条路。

<a id="chapter-06-section-05"></a>

### Trie 与 Radix Tree【认识】

Trie 按前缀逐层组织字符串，例如所有以同样几个字母开头的单词共享一段路径。输入前缀后，可以直接进入对应子树，寻找候选词，适合自动补全和路由前缀匹配。Radix Tree 将没有分叉的长路径压缩，减少节点开销。与哈希不同，它保留字符串前缀结构。代价是节点和指针可能占据较多空间，具体是否高效取决于字符集合和压缩方式。

<a id="chapter-06-section-06"></a>

### Fenwick Tree 与 Segment Tree【认识】

数组反复发生更新，同时又要频繁询问区间统计时，预先算一次前缀和就不够了。Fenwick Tree，也叫树状数组，维护特定区间的累积信息，常用于动态前缀和以及频率统计。Segment Tree，线段树，把区间递归分成左右两部分，可维护区间最小值、最大值和其他可组合信息。它更通用，但实现与空间开销通常也更大。共同思想是只更新受影响的摘要，不重新扫描整段数据。

<a id="chapter-06-section-07"></a>

### Skip List，跳表【认识】

跳表在有序链表上增加若干层快捷通道：先在高层跨过大段数据，再下降到低层精确定位。用随机方式决定节点能出现在多少层，可以避免复杂的树旋转，同时得到良好的平均查找效率。它适合实现有序集合或某些并发索引。它不是哈希表，也不是二叉树；优势来自多级导航。最坏情况、随机层高以及内存布局仍然需要工程控制。
