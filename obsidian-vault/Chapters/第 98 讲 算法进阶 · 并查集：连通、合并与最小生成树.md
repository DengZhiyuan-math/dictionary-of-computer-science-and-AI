## 第 98 讲｜算法进阶 · 并查集：连通、合并与最小生成树

领域：算法进阶与面试推理 · 细讲

<a id="chapter-98-section-01"></a>

### Find 与 Union：代表元不是业务标签

并查集 Disjoint Set Union 管理互不重叠的集合。find 返回当前集合的代表，union 合并两组；判断两个节点是否连通，比较代表是否相同。根可以因合并而改变，不能把根编号当作永久业务 ID。

先给每个节点独立的 parent。合并前必须先找两侧根；若根相同，集合数不变。只把任意节点的父指针改到另一节点，可能破坏结构或失去性能保证。

<a id="chapter-98-section-02"></a>

### 按大小合并与路径压缩的成本

按大小合并把较小树接到较大树根下。路径压缩在 find 时改写访问路径，让后续查找更短；它改变树形，不改变集合成员关系。

两者结合时，一串操作的摊还成本可用逆 Ackermann 函数 α(n) 表示，近似 O(α(n)) 每操作。它不是严格 O(1) 的单次最坏保证；初始化与保存 parent、size 仍要 O(n) 时间和空间。

<a id="chapter-98-section-03"></a>

### Kruskal：连通性怎样帮助避开环

最小生成树要求连接无向图全部顶点，并最小化所选边的总权。Kruskal 按边权从小到大尝试；如果两端已在同一集合，加入这条边会形成环，因此跳过。

图不连通时得到最小生成森林。主要成本通常来自边排序 O(E log E)，并查集部分接近 O(E α(V))；负边权本身不妨碍这种生成树算法。最短路与最小生成树优化的对象不同。

<a id="chapter-98-section-04"></a>

### 删除、回滚与加权并查集的边界

普通并查集擅长只增加连接的在线查询，不能直接把一次 union 反向操作来处理任意删除。离线动态连通、可回滚结构等需要额外设计；回滚时通常避免直接使用难以恢复的路径压缩。

带权并查集还会保存节点到父节点的相对量，例如差值或比例。压缩路径时必须同步组合这些关系；不要把最短路径边权直接套进并查集的“权重”，二者含义不同。

<a id="chapter-98-section-05"></a>

### 案例 31：并查集：重复连接不减少集合数

场景与输入：六个节点 0…5，依次加入无向连接 (0,1)、(2,3)、(1,2)、(0,3)、(4,5)。

手算第 1 步：最初集合数为 6。前两次分别合并两组，集合数变为 4。

手算第 2 步：合并 (1,2) 后，0、1、2、3 属于同一集合，集合数变为 3。

手算第 3 步：再次连接 (0,3) 时两端根已相同，不执行合并；最后 (4,5) 把集合数降到 2。

结果与解释：最终两组为 {0,1,2,3}、{4,5}。具体代表元依合并策略而变，成员划分不变。

易错点与边界：不要每读到一条边就把集合数减一；重复边或成环边可能不产生新合并。

改变条件再想一想：去掉 (1,2)，仍加入 (0,3)，最后几组？

自测参考：仍是 2 组，(0,3) 会把先前分离的 {0,1} 与 {2,3} 合并。
