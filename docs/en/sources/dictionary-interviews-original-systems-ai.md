## Formula and complexity checks

The independently computed unweighted losses use natural logarithms:

- Binary cross-entropy from a logit: `max(z,0) - y*z + log1p(exp(-abs(z)))`; its derivative is `sigmoid(z)-y`.
- Multiclass cross-entropy at index y: `log(sum(exp(z_j))) - z_y`, evaluated by subtracting the maximum logit for stability. Computing a batch of B examples and C classes takes `O(B*C)` arithmetic.
- Unequal microbatch means: `L=sum(n_i*L_i)/sum(n_i)` for the explicitly stated additive per-example objective. Parameter gradients require `O(P)` storage regardless of the number of accumulation steps; model activations and forward/backward work are separate.
- Binary F1: `2*TP/(2*TP+FP+FN)`. One fixed threshold takes `O(n)` time and constant extra counting space. Selecting among all score cutoffs generally adds sorting.
- Dense KV bytes: `2*L*B*H_kv*T*d_h*bytes_per_element`. Single-token dense attention arithmetic is `O(L*B*H_q*T*d_h)` under equal key/value head dimensions, excluding projections, feed-forward layers, and cache-copy costs.

For systems questions, database contention, storage, optimizer choices, and network latency prevent an unconditional end-to-end `O(1)` claim. A balanced B-tree range scan is commonly modeled as `O(log N + k)` under the stated index/access assumptions; a wait-for graph cycle check can be modeled as `O(V+E)`. These are analysis models, not promises about PostgreSQL internals or wall-clock latency.

## Independent verification and remaining limits

Run `node scripts/check-english-original-systems-ai.mjs`. It reads the translated question records, checks their worked outputs, and exercises finite state traces and bounded numeric variants without third-party packages or network access. It compares weighted accumulation with flattened per-example means, stable losses with finite differences, attention masking with visible-key normalization, and rank-based AUC with an independent sorted-rank calculation.

State models do not establish crash consistency of a deployed order service, concurrent PostgreSQL behavior, real Redis expiration timing, HTTP cache interoperability, or thread scheduling fairness. Numeric checks do not execute PyTorch, GPU kernels, or scikit-learn; primary documentation supplies the API contract. These distinctions are intentional and must remain visible in any publication claim.
