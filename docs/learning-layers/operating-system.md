# Operating System

概念编号：`concept:operating-system` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/operating-system/)

## 第一层：概念入门 · 知其然

### 先分清：程序、处理器、内存与存储设备

程序（program）是一组规定计算步骤的指令；指令（instruction）是处理器能够识别的一项基本操作要求，例如相加、读取数据，或按判断结果选择后续步骤。中央处理器（central processing unit，CPU）执行这些指令。程序保存成文件时，只是一份存放着的指令和数据，还没有形成一次正在推进的运行。

程序运行时，需要存放当前指令、输入和中间结果。这里的内存（main memory，通常由 RAM，即 random-access memory 实现）指运行中的工作存储空间；常见 RAM 断电后不能保留内容。固态硬盘（solid-state drive，SSD）等存储设备（storage device）用于较长期保存程序和文件。编辑器中尚未保存的一段文字与硬盘中的文档文件，因此可以有不同内容。

多个程序都需要处理器、内存和设备，但不能任意抢占或改写对方的资源。谁获得执行机会，哪些内存可以访问，文件能否打开，这些问题需要统一的管理规则。下面讨论现代通用计算机上的操作系统；专用设备也可能采用不同的组织方式。


### 定义

操作系统（operating system，OS）是管理计算机硬件资源，并为应用程序提供执行环境和公共服务的系统软件。这里的资源包括处理器执行时间、内存空间及存储和输入输出设备；公共服务包括创建与结束程序运行、访问文件、收发设备数据和检查访问权限。它既决定资源怎样分配，也提供程序使用资源时必须遵守的接口与保护机制。Windows、macOS 和采用 Linux 内核的系统都是常见例子。

### 理解定义中的术语与关系

#### 进程（process）：一次程序运行需要被记录什么

进程是操作系统管理的一次程序运行的实例，连同这次运行的执行状态和资源环境。操作系统需要记录它执行到了哪里、哪些内存属于它、打开了哪些文件，以及它以什么身份和权限运行。程序文件描述“怎样做”，进程则包含“这一次做到哪里、正在使用什么”。同一程序可以有多个进程，各自处理不同文档；暂停或等待中的进程仍然存在，不能把“进程”只理解为此刻正在占用 CPU 的程序。窗口与进程也不一一对应：一个进程可以管理多个窗口，一个应用也可以使用多个进程。

#### 地址空间（address space）：内存位置怎样属于某个进程

程序通过地址（address），即标识内存位置的数值，读取和修改数据。现代通用操作系统通常给每个进程提供自己的虚拟地址空间（virtual address space）：程序使用的是这个空间中的地址，操作系统与处理器共同把这些地址对应到实际物理内存，并检查访问是否允许。因此，两个进程都使用数值为 4096 的地址，并不表示它们读写同一份数据；必须连同“哪个进程的地址空间”一起理解。默认隔离可防止普通进程随意访问对方的私有内存；显式安排的共享内存（shared memory）则允许部分数据被共同访问。地址空间也不是承诺给每个进程无限量的物理内存。

#### 线程（thread）与调度（scheduling）：谁获得执行机会

一个进程可以包含一条或多条执行线索，称为线程。每条线程记录自己的执行位置和必要的临时状态；同一进程中的线程通常共享该进程的地址空间和已打开的文件。调度是操作系统选择让哪条可运行线程使用处理器的过程。为看清原理，本节的例子都限定为每个进程只有一条线程，因此可以直接说“让进程 A 或 B 运行”。这是一项简化；实际系统通常以线程为主要调度对象，处理器核心（processor core）是处理器中能够执行程序指令的硬件计算单元，不能把进程、线程和核心当作同一个对象。

#### 运行、就绪与阻塞（running、ready、blocked）：没在计算有两种原因

正在使用处理器执行指令，叫运行；已经具备执行条件、只等处理器分配，叫就绪；必须等待尚未发生的事件，叫阻塞。例如，读取的数据尚未从设备返回时，依赖这些数据的下一步不能继续，这条线程可以进入阻塞状态。操作系统此时能把处理器交给其他就绪线程；若没有其他可运行工作，处理器就可能空闲。所等事件完成后，阻塞线程通常先变为就绪，再等调度，不保证立即运行。输入输出（input/output，I/O）指程序与文件、网络或设备之间的数据交换；这里讨论等待操作完成后才继续的阻塞式 I/O，实际也存在其他方式。

#### 上下文切换（context switch）：暂停后怎样接着做

从一条线程改为执行另一条线程时，操作系统必须保存前者恢复运行所需的处理器状态，例如执行位置和计算中的临时值，再恢复后者先前保存的状态；这称为上下文切换。暂停并不等于重新启动，恢复时通常接着原来的步骤推进。切换也不要求每次把整个进程的内存复制到硬盘。它有时间成本，因此更频繁地轮流执行不等于凭空增加计算能力。对计算机系统而言，单核上的交替推进称为并发（concurrency）；多个核心在同一时间执行不同工作，是硬件并行（parallelism）的一种情形。

#### 内核（kernel）与系统调用（system call）：程序怎样请求受控服务

内核是操作系统中负责核心资源管理、处理受保护操作的部分。处理器提供不同权限的执行模式：普通应用通常在受限制的用户态（user mode）执行，内核代码在权限更高的内核态（kernel mode）执行。用户态程序需要打开文件等服务时，通过规定入口提出请求，这个机制叫系统调用；通常由程序使用的软件库封装细节。内核检查请求参数和权限，执行允许的操作，返回结果或错误，再恢复应用执行。这不是把“内核权限”交给应用，也不保证每次请求成功。普通加法、访问已经可用且允许访问的内存，通常由 CPU 直接执行，并不需要为每一步都调用操作系统。

#### 文件系统（file system）与驱动程序（device driver）：从文件名到设备

文件（file）是操作系统提供的命名数据对象；文件系统负责组织文件名、目录、数据存放位置和相关记录，使程序可以按文件访问，而不必自己决定设备上的每个存储位置。驱动程序是与特定设备交互的软件，把较统一的设备请求转成该设备需要的操作。以读文件为例：应用提出请求，内核按文件系统规则定位内容、检查访问条件；若数据尚不在可用的内存副本中，再通过设备及其驱动取得数据，之后把结果交给应用。并非每次读文件都要实际访问硬盘，也并非每次读请求都会阻塞。

### 概念边界与常见混淆

这里的隔离与权限管理（access control）限制的是哪些操作被允许，并不判断操作是否符合用户的真实意图：有权写入某个文件的程序，仍可能把正确内容覆盖成错误内容。多个进程也可以合法共享同一文件，内存隔离不会自动解决共同写文件的冲突。桌面、窗口和图标属于图形用户界面（graphical user interface，GUI），不能代表操作系统的全部；没有桌面的服务器仍然需要上述资源管理与服务。本节不展开具体调度算法或地址映射的数据结构，但不能因此省略这些机制所解决的问题。

### 先看一个例子

以“打开一份文档、修改一个词、保存并退出”为例，同时还有下载程序工作。假设编辑器和下载程序各用一个单线程进程；编辑器采用阻塞式文件读取，最初所需文件内容还没有可用的内存副本；也不启用自动保存。以下是一条说明机制的可能执行过程，不是所有操作系统固定采用的逐指令顺序。

1. 启动：用户发起打开编辑器的操作后，相关系统服务建立编辑器进程，准备它的地址空间和初始执行状态，把程序运行所需内容安排到可访问的位置。调度器选择其线程后，CPU 才开始推进这次执行。建立进程不等于预先把整个程序文件全部读入物理内存。
2. 请求文件：编辑器通过系统调用请求打开文档。内核检查它是否有相应访问权限；成功后，编辑器取得用于后续引用这个已打开文件的标识，再请求读取内容。若打开失败，程序应处理错误，不能继续假设文档已可读。
3. 等待与切换：本例所需数据尚未就绪，文件读取需要等待设备完成。编辑器线程因此阻塞。若下载程序的线程已就绪，操作系统保存编辑器的执行状态，再让下载程序使用 CPU；编辑器并没有退出，也不会在等待期间一直占用这个核心进行计算。
4. 恢复与修改：数据可用后，编辑器线程重新就绪，获得调度时继续读取之后的步骤。用户修改一个词，编辑器先改变其内存中的文档内容。此时仅凭屏幕文字已变，不能认定存储设备上的文件也已经更新；没有自动保存的前提在这里很重要。
5. 保存：编辑器通过文件服务请求写入新内容，并处理成功或失败的结果。一次普通写入成功，可能只表示数据已被操作系统接收并暂存在内存中，尚未到达能抗断电的存储状态。需要抵抗突然断电时，还要采用适合该系统的持久化操作和正确的保存流程；不能把界面显示“已保存”、一次写入返回、数据已经持久保存当成完全相同的保证。
6. 退出：编辑器结束运行后，操作系统回收这次进程运行持有的私有资源并处理未关闭的文件等资源。已持久保存的文档不因为进程结束而消失；尚未保存且没有其他副本的修改则不能指望由进程回收自动补存。整个过程同时体现了进程管理、调度、内存隔离、系统调用和文件设备服务。

### 理解练习

#### 1. 同一个程序文件与两次运行

明确假设同一编辑器程序被启动成两个不同进程，分别编辑文档 A 和 B。两者必须使用两份不同的程序文件吗？修改 A 的内存内容会自动修改 B 吗？仅看到两个窗口，能否反过来断定存在两个进程？

<details><summary>答案与解释</summary>

不需要两份程序文件：同一份程序可以支持不同的运行实例。两次运行各有自己的执行状态，普通私有内存中的修改不会自动传给另一进程；若希望共同编辑，需要程序显式交换或共享数据。两个窗口也不必对应两个进程，一个进程可以管理多个窗口。本题之所以能讨论两个独立进程，是题目明确给定，而不是由窗口数量推断。

</details>

#### 2. 内存里改了，文件是否也改了

硬盘上的文档原来写着“原稿”。编辑器读入后改成“修订稿”，没有执行保存，也没有自动保存或恢复副本，然后进程崩溃。重新打开文件能否保证看到“修订稿”？这里哪一份数据改变了？

<details><summary>答案与解释</summary>

不能。改变的是编辑器进程内存中的文档内容，题目没有给出把改动写回文件的步骤。进程崩溃不会自动把私有内存中的修改补写到文件，因此按这些条件，文件仍是“原稿”。若实际软件有自动保存或恢复功能，结论可能不同，必须检查这些额外机制，不能把它们当作内存本身的性质。

</details>

#### 3. 相同地址为什么不是同一份数据

两个普通进程都报告“我的地址 4096 存着一个数”，且题目说明两处都是各自的私有内存，没有建立共享。能否因此说它们读写同一物理位置？进程 A 能否仅凭知道这个数值就修改 B 的数据？

<details><summary>答案与解释</summary>

不能。这里的数值属于各自的虚拟地址空间，解释地址必须带上进程这个背景。操作系统与硬件对不同进程的地址进行相应映射和权限检查；A 使用自己的地址 4096，访问的是 A 的对应位置，不会仅凭这个数值切到 B 的地址空间。显式共享或特殊授权会改变可访问关系，本题已经排除共享，并不声称任何权限配置下都绝无越界风险。

</details>

#### 4. 逐步追踪：等待设备时 CPU 在做什么

只考虑一个 CPU 核心和两个单线程进程，任一时刻只执行其中一条线程，忽略系统调用与切换开销。A 从第 0 毫秒开始计算 1 毫秒，随后发起一次读取；设备从请求时刻起恰好用 4 毫秒才使数据可用，A 得到数据后还需计算 1 毫秒。B 在第 0 毫秒已就绪，只需计算 3 毫秒。约定 A 读取等待时立即运行 B。请列出时间线，指出 B 完成时间、A 完成时间，以及 CPU 是否一直有工作。

<details><summary>答案与解释</summary>

第 0—1 毫秒运行 A。读取请求在第 1 毫秒发出，因此数据到第 5 毫秒才可用，不是第 4 毫秒。A 阻塞期间，第 1—4 毫秒运行 B，B 在第 4 毫秒完成；第 4—5 毫秒，A 仍在等数据，B 已结束，按题设没有其他工作，因此 CPU 空闲。第 5—6 毫秒 A 恢复计算并完成。CPU 共计算 5 毫秒，整个过程经过 6 毫秒。这个例子既说明等待可与别的计算重叠，也说明重叠不是保证：只有存在就绪工作时，调度才能利用这段等待。

</details>

#### 5. 哪些操作需要请求内核服务

比较三件事：对已经可用的私有内存中的两个数相加；调用一个只完成这次加法的软件函数；请求打开一个本来没有访问权限的文件。是否每件事都必须发生系统调用？最后一个请求会因为“已经进入内核”就得到许可吗？

<details><summary>答案与解释</summary>

普通加法通常可由 CPU 在用户态直接完成；把它封装成函数，也不会仅因为发生函数调用就变成系统调用。文件打开则需要操作系统的文件服务，通常通过软件库发起相应系统调用。进入内核只是让有权执行检查的代码处理请求，不是给请求者授予额外权限；在题目权限条件不变时应拒绝打开并返回错误。程序必须处理错误，不能把“提出请求”当作“取得资源”。

</details>

#### 6. 进入内核与换一个进程是同一件事吗

编辑器发出一个能立即完成的系统调用，内核检查并返回，期间没有调度其他进程。有人据此说“既然用户态变成内核态，就一定从编辑器切换到了另一个独立的内核进程”。这个说法成立吗？

<details><summary>答案与解释</summary>

不成立。用户态与内核态描述代码执行时的权限级别；进程与线程切换描述当前执行实例是否改变。在常见实现中，系统调用可以由同一线程进入内核执行服务，再回到原来的用户态步骤，不需要先调度另一个进程。因此，发生系统调用不意味着必然发生进程间上下文切换；若请求必须等待，当前线程可能阻塞，调度器可选择其他就绪线程；即使不阻塞，也可能因其他调度原因发生切换。不同系统的内部实现可以不同，但不能把这两个概念直接等同。

</details>

#### 7. 有内存隔离，为什么还会互相覆盖文件

两个进程的私有内存已经隔离，但两者都被授予写同一文档文件的权限。A 写入自己的版本，随后 B 又把旧版本整体写回。操作系统是否应该仅凭“B 的内容更旧”自动拒绝？怎样理解这里保护的边界？

<details><summary>答案与解释</summary>

通常不能这样期待。内存隔离限制私有内存访问，文件权限决定谁可以请求写文件；两者都没有定义哪份文档才是用户想保留的版本。B 的写入可能完全符合访问权限。避免丢失 A 的修改，需要应用或协作系统另行约定版本检查、编辑协调或保留历史等规则。操作系统提供受控访问的基础，但不会自动理解每个应用的数据含义和编辑意图。

</details>

#### 8. 写入成功是否已经能抵抗断电

假设应用的一次普通文件写入已成功返回，但数据还只在操作系统的内存暂存区，尚未到达可抗断电的设备存储。立即断电后，能否保证新内容仍在？结束进程和突然断电是否具有相同影响？

<details><summary>答案与解释</summary>

不能保证，题目明确说明持久保存尚未完成；成功返回在这里表示数据已被系统接收，并不等于所有持久化步骤都结束。单独结束应用进程通常不会使操作系统的暂存数据立刻消失，系统仍可能继续完成写出；突然断电却会影响常见易失内存中的数据，两者不能混为一谈。需要明确的抗断电保证时，应使用该系统提供的持久化机制并检查结果，同时考虑应用保存流程和设备所承诺的保证。

</details>

## 第二层：深入理解 · 知其所以然

围绕推导、计算、应用与推广阅读；下面保留原有推演顺序。

### 从条件一步步推导

1. 调度器选择可运行任务；任务等I/O时阻塞，可把CPU让给别人。
2. 虚拟内存提供每进程地址空间，页表与权限控制映射和隔离。

### 具体输入与计算步骤

单核用2毫秒时间片轮流运行A、B，两者各需4毫秒CPU。

1. 忽略切换成本，0至2运行A、2至4运行B。
2. 4至6再运行A完成，6至8运行B完成，总CPU时间8毫秒。

计算结果：4至6再运行A完成，6至8运行B完成，总CPU时间8毫秒。

### 换到实际问题中应用

服务吞吐突然降低但CPU不满。

1. 检查线程是否等待I/O、锁或内存换页，区分可运行与阻塞状态。
2. 按等待来源优化，增加线程不一定能缓解锁竞争。

应用结论：按等待来源优化，增加线程不一定能缓解锁竞争。

### 原有解释与进一步例题


### 定义

操作系统管理进程、线程、内存与设备，并向应用提供受控接口。进程提供资源与隔离边界，线程是进程内部的执行单元；锁和死锁属于并发机制，不能代替操作系统本身的定义。


### 参数与公式

虚拟地址由进程地址空间映射，系统调用进入内核完成受保护的操作。调度器分配执行机会，文件描述符等句柄引用系统资源。并发表示任务时间区间重叠，是否同时在不同核心执行还取决于硬件与调度。


### 例子

两个进程各自使用虚拟地址 0x1000，可以映射到不同物理内存。一个进程的两个线程通常共享地址空间，同时更新共享计数可能发生竞争；需要按并发契约同步，不能因地址相同就把跨进程和进程内共享混为一谈。


### 适用边界与常见误解

Concurrency and parallelism describe task progress and execution; blocking and asynchrony describe waiting and control flow.
