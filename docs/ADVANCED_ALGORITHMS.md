## 第 98 讲｜算法进阶 · 并查集：连通、合并与最小生成树

领域：算法进阶与面试推理 · 细讲

<a id="chapter-98-section-01"></a>

### Find 与 Union：代表元不是业务标签

并查集 Disjoint Set Union 管理互不重叠的集合。find 返回当前集合的代表，union 合并两组；判断两个节点是否连通，比较代表是否相同。根可以因合并而改变，不能把根编号当作永久业务 ID。

先给每个节点独立的 parent。合并前必须先找两侧根；若根相同，集合数不变。只把任意节点的父指针改到另一节点，可能破坏结构或失去性能保证。

<a id="chapter-98-section-02"></a>

### 按大小合并与路径压缩的成本

按大小合并把较小树接到较大树根下。路径压缩在 find 时改写访问路径，让后续查找更短；它改变树形，不改变集合成员关系。

两者结合时，一串操作的摊还成本可用逆 Ackermann 函数 α(n) 表示，近似 O(α(n)) 每操作。它不是严格 O(1) 的单次最坏保证；初始化与保存 parent、size 仍要 O(n) 时间和空间。

<a id="chapter-98-section-03"></a>

### Kruskal：连通性怎样帮助避开环

最小生成树要求连接无向图全部顶点，并最小化所选边的总权。Kruskal 按边权从小到大尝试；如果两端已在同一集合，加入这条边会形成环，因此跳过。

图不连通时得到最小生成森林。主要成本通常来自边排序 O(E log E)，并查集部分接近 O(E α(V))；负边权本身不妨碍这种生成树算法。最短路与最小生成树优化的对象不同。

<a id="chapter-98-section-04"></a>

### 删除、回滚与加权并查集的边界

普通并查集擅长只增加连接的在线查询，不能直接把一次 union 反向操作来处理任意删除。离线动态连通、可回滚结构等需要额外设计；回滚时通常避免直接使用难以恢复的路径压缩。

带权并查集还会保存节点到父节点的相对量，例如差值或比例。压缩路径时必须同步组合这些关系；不要把最短路径边权直接套进并查集的“权重”，二者含义不同。

<a id="chapter-98-section-05"></a>

### 案例 31：并查集：重复连接不减少集合数

场景与输入：六个节点 0…5，依次加入无向连接 (0,1)、(2,3)、(1,2)、(0,3)、(4,5)。

手算第 1 步：最初集合数为 6。前两次分别合并两组，集合数变为 4。

手算第 2 步：合并 (1,2) 后，0、1、2、3 属于同一集合，集合数变为 3。

手算第 3 步：再次连接 (0,3) 时两端根已相同，不执行合并；最后 (4,5) 把集合数降到 2。

结果与解释：最终两组为 {0,1,2,3}、{4,5}。具体代表元依合并策略而变，成员划分不变。

易错点与边界：不要每读到一条边就把集合数减一；重复边或成环边可能不产生新合并。

改变条件再想一想：去掉 (1,2)，仍加入 (0,3)，最后几组？

自测参考：仍是 2 组，(0,3) 会把先前分离的 {0,1} 与 {2,3} 合并。

参考资料（不朗读）：[S178 · Princeton Algorithms — Union-Find](https://algs4.cs.princeton.edu/15uf/)

## 第 99 讲｜算法进阶 · 有权最短路：松弛、优先队列与负环

领域：算法进阶与面试推理 · 细讲

<a id="chapter-99-section-01"></a>

### 松弛：距离数组是一组上界

松弛边 u→v 的意思是检查 dist[u]+w 是否比 dist[v] 更小；如果更小，就更新距离并记录前驱。初始源点为 0，其余为不可达，不能把不可达占位值参与普通加法。

距离初次被发现并不一定最终确定。先问图有向还是无向、边权是否相同、是否允许负值；这些约束决定何时可以确认答案。找不到路径应明确返回不可达，而不是某个碰巧很大的正常距离。

<a id="chapter-99-section-02"></a>

### Dijkstra 与过期堆条目

非负边权下，总是取当前暂定距离最小的节点，可以按次序确认最短距离。使用最小堆时，改进一个节点的距离可以插入新条目；旧条目保留到弹出时再判断是否过期。

若弹出的 d 已不等于 dist[u]，跳过该条目。邻接表加二叉堆、采用这种懒删除实现，时间可写 O((V+E) log(V+E))，堆空间最坏 O(E+1)；不能把用数组反复排序的教学展示误称为堆的性能。

<a id="chapter-99-section-03"></a>

### 0-1 BFS：队列两端代表两层距离

当边权只有 0、1 时，可以使用双端队列维护距离次序。经权 0 的边得到更短距离时放队首，经权 1 的边放队尾。判断条件仍是能否改进 dist，不能照搬普通 BFS 的“第一次发现永不修改”。

例如 A→B 权 1，A→C 权 0，C→B 权 0，B 初次得到 1，后来应被改进为 0。典型实现的整体复杂度为 O(V+E)，双端操作需要真正高效，数组 shift 的线性代价会改变实现成本。

<a id="chapter-99-section-04"></a>

### Bellman-Ford 与负环影响范围

允许负边时，可重复扫描全部边进行松弛。在没有源点可达负环的情况下，简单最短路至多含 V-1 条边，最多 V-1 轮足够；没有任何更新时可以提前结束。

额外一轮仍能改进的可达节点提示负环影响，随后可沿出边传播受影响范围。源点不可达的负环不会使该源点的全部距离失效；从负环也无法到达的节点未必受影响。标准时间 O(VE)，距离空间 O(V)，另加图存储。

<a id="chapter-99-section-05"></a>

### 案例 32：Dijkstra：旧距离为什么还在队列里

场景与输入：有向边 A→B=5、A→C=1、C→B=1、B→D=2、C→D=7；从 A 出发。

手算第 1 步：处理 A 后，候选 B=5、C=1。先处理 C，把 B 改进为 2、D 改进为 8。

手算第 2 步：处理新 B=2 后，D 改进为 4。队列里仍可能保留旧 B=5 和旧 D=8。

手算第 3 步：随后取 D=4；弹出 B=5 时发现它不等于当前 dist[B]=2，跳过；D=8 同理。

结果与解释：距离 A=0、C=1、B=2、D=4，最短路线 A-C-B-D。

易错点与边界：演示按小列表排序展示候选，不是高效堆实现；理论堆复杂度不适用于该展示容器。

改变条件再想一想：允许 C→B=-4 时还能套同一个非负权证明吗？

自测参考：不能；负边可能让已经确认的距离再次下降，应根据约束改用其他方法。

<a id="chapter-99-section-06"></a>

### 案例 33：0-1 BFS：第一次发现不一定最短

场景与输入：有向边 A→B=1、A→C=0、C→B=0，从 A 求到 B 的最小代价。

手算第 1 步：处理 A 时，B 暂定为 1，放队尾；C 暂定为 0，放队首。

手算第 2 步：先处理 C，经 C→B 得到新代价 0，比 1 更小，更新 B 并放到队首。

手算第 3 步：最终 B 的距离为 0，路径是 A-C-B；虽然它使用两条边，却比一条边的直达代价更低。

结果与解释：0-1 BFS 按距离改进松弛，不能把普通等权 BFS 的访问标记规则原样使用。

易错点与边界：把“入队过”当作“永不更新”，会错误保留 B=1；权重为 2 时也不能继续沿用该双端队列规则。

改变条件再想一想：如果三条边全为 1，最少代价是多少？

自测参考：1，A→B 的直达路线就最短，此时普通 BFS 足够。

<a id="chapter-99-section-07"></a>

### 案例 34：负环：先问它是否可达

场景与输入：节点 A、B、C、D、E；边 A→B=2、B→C=1、D→E=-2、E→D=1，从 A 出发。

手算第 1 步：从 A 只能到 B、C，最短距离分别为 2、3。D-E-D 总权为 -1，但从 A 无法到达。

手算第 2 步：扫描边时，不可达节点不参与松弛，因此这个负环不影响 A、B、C 的距离。

手算第 3 步：额外加 C→D=0 后，负环变为可达。D、E 可反复绕环降低代价，若再有 E→B，B、C 也会受到影响。

结果与解释：负环影响取决于源点可达性及从负环能到达谁，不等于整张图每个节点都没有答案。

易错点与边界：有限轮中得到的很小负数不是受负环影响节点的真正最短距离；应标记无有限下界。

改变条件再想一想：未增加 E→B 时，A 的距离仍为 0 吗？

自测参考：是，因为负环无法返回 A；其影响不会逆着不存在的边传播。

参考资料（不朗读）：[S179 · MIT 6.006 — Shortest Paths](https://courses.csail.mit.edu/6.006/spring11/lectures/lec14.pdf)；[S180 · MIT 6.006 — Bellman-Ford](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-fall-2011/5edb13fb34cbe7f4cdccc13d131772e7_MIT6_006F11_lec17.pdf)；[S181 · CP-Algorithms — 0-1 BFS](https://cp-algorithms.com/graph/01_bfs.html)

## 第 100 讲｜算法进阶 · 区间结构：差分、Fenwick 与线段树

领域：算法进阶与面试推理 · 细讲

<a id="chapter-100-section-01"></a>

### 先用操作组合选择结构

静态区间和可用前缀和预处理，之后 O(1) 查询；大量区间加、最后一次还原，可以记录差分的两个端点变化。结构选择先看“更新什么、查询什么、在线还是离线”，不要一上来就建最复杂的树。

差分在一基或零基表示中都可实现，但右端点之后的撤销位置必须预留。区间 [l,r] 加 x，就是差分 l 处加 x、r+1 处减 x；最终做前缀累加还原。

<a id="chapter-100-section-02"></a>

### Fenwick：用二进制划分前缀

一基 Fenwick Tree 的 tree[i] 保存长度 lowbit(i) 的一段区间和。lowbit(i)=i 与负 i 按位与，在适当整数表示下取得最低有效的 1 位。

查询前缀 i 时累计 tree[i]，再令 i 减 lowbit(i)；单点加时从该位置出发，反复加 lowbit(i) 更新受影响块。两种操作都走 O(log n) 个节点，空间 O(n)。更新索引 0 会导致无法前进，因此要保护一基接口。

<a id="chapter-100-section-03"></a>

### 线段树：节点保存可以合并的信息

线段树把区间递归分成两半，父节点保存两侧可合并的摘要，例如 sum、min、max 或计数。查询区间拆成少量完整覆盖的节点，再合并答案；单点修改只重算根到叶的一条路径。

常见实现构建 O(n)，单点修改和区间查询 O(log n)，空间 O(n)。摘要与合并顺序需要符合任务；最大值不能通过两个前缀最大值相减得到，这也是它与区间求和不同之处。

<a id="chapter-100-section-04"></a>

### Lazy propagation 与不合适的运算

区间更新时，完全覆盖的节点可先更新摘要，再留下尚未传给孩子的标记。向下访问前才传播；区间加时，sum 需要增加“长度乘增量”，max 则只加一次增量。

多个标记的复合要有清楚次序：先赋值再加与先加再赋值结果不同。普通 Fenwick 的前缀差做法依赖可以消去前缀的运算；不能把它无条件推广成任意区间最小值查询。

<a id="chapter-100-section-05"></a>

### 案例 35：Fenwick：查询与更新沿不同方向走

场景与输入：一基数组 a=[2,1,3,4,2]。tree 保存区间和，初始 tree[1…5]=[2,3,3,10,2]。

手算第 1 步：查询前 5 项，先读 tree[5]=2，索引减 lowbit(5)=1 到 4，再读 tree[4]=10，得到 12。

手算第 2 步：把位置 3 加 2，先让 tree[3] 从 3 到 5，再让 tree[4] 从 10 到 12；下一索引 8 超过 n，停止。

手算第 3 步：更新后前 5 项为 14；位置 2…4 的和为 prefix(4)-prefix(1)=12-2=10。

结果与解释：Fenwick 只更新包含该位置的二进制区间块；每条查询或更新路径至多 O(log n) 步。

易错点与边界：下标 0 不适合作为这个一基更新接口的起点，因为 lowbit(0)=0。

改变条件再想一想：位置 3 的增量改成 -2，前 5 项是多少？

自测参考：10。原总和 12 减 2，结构同样支持负增量。

<a id="chapter-100-section-06"></a>

### 案例 36：线段树：查询最大值不能做前缀相减

场景与输入：数组 [2,1,3,4,2,6]，零基半开查询 [1,5)，目标是区间最大值。

手算第 1 步：目标元素为 [1,3,4,2]，最大值是 4；不包括下标 5 的 6。

手算第 2 步：用线段树将区间分解成覆盖节点，按 max 合并各节点摘要，合并身份元可以是负无穷。

手算第 3 步：若把下标 2 从 3 改为 9，只需更新相关叶和祖先；再次查询 [1,5)，结果为 9。

结果与解释：节点保存什么由查询目标决定。sum、max 与更复杂摘要的合并规则不同。

易错点与边界：prefixMax(5)-prefixMax(1) 不会得到区间最大值；空区间返回约定也必须明确。

改变条件再想一想：如果所有值都是负数，合并初值设为 0 对吗？

自测参考：不对，0 可能大于所有真实值；应使用适当身份元或显式处理空结果。

<a id="chapter-100-section-07"></a>

### 案例 37：差分：区间结束之后撤销增量

场景与输入：零基长度 5 的全零数组。先对闭区间 [1,3] 加 2，再对 [2,4] 加 -1，最后统一还原。

手算第 1 步：预留长度 6 的差分，第一次在 d[1] 加 2、d[4] 减 2。

手算第 2 步：第二次在 d[2] 减 1、d[5] 加 1，d[5] 是末尾之后的撤销哨兵。

手算第 3 步：对前五个差分做累加，得到位置 0=0、1=2、2=1、3=1、4=-1。

结果与解释：最终 [0,2,1,1,-1]，每次区间更新只改两个端点，最后 O(n) 还原。

易错点与边界：闭区间撤销位置是 r+1，不是 r；哨兵需要分配空间，但不作为原数组第六个结果。

改变条件再想一想：改成半开区间 [l,r)，撤销在哪？

自测参考：在 d[r]，因为 r 已经不属于被更新区间。

## 第 101 讲｜算法进阶 · 字符串匹配：KMP、Trie 与多模式

领域：算法进阶与面试推理 · 细讲

<a id="chapter-101-section-01"></a>

### 前缀函数：失配后还剩多少可复用信息

前缀函数 π[i] 表示子串 s[0..i] 的最长相等真前缀与后缀长度。“真”表示不能使用整个子串本身。已经匹配 j 个字符后失配，可以让 j 退到 π[j-1]，复用仍然相等的边界。

例如 ababaca 的 π 为 [0,0,1,2,3,0,1]。构造时字符位置持续向前，候选边界向后回退；总回退次数受已增加次数限制，不是每次失配都从头比较所有前缀。

<a id="chapter-101-section-02"></a>

### KMP：文本指针不后退的单模式搜索

KMP 为模式先构造前缀函数，再顺序读取文本。当前字符不匹配时只沿模式边界回退；匹配长度达到模式长度时报告一个匹配位置。

若允许重叠匹配，报告之后退到 π[m-1] 再继续；不能把匹配长度总是清零。文本长度 n、模式长度 m 时，典型实现 O(n+m) 时间、O(m) 额外空间。空模式的返回约定要单独定义。

<a id="chapter-101-section-03"></a>

### Trie 与 Aho-Corasick：前缀和后缀各做什么

Trie 共享多个词的前缀，能回答某词是否存在和某串是否为前缀；结束标记区分完整词与路径中间节点。它并不自动让长文本中的所有多模式匹配成为线性扫描。

Aho-Corasick 在 Trie 上补失败链接，失配时转到仍可能有用的后缀状态，并正确处理该状态上的输出。例如匹配 she 的位置也可能同时结束 he。复杂度需声明字符表与转移实现，并另计实际输出数量。

<a id="chapter-101-section-04"></a>

### 滚动哈希：快速比较仍需考虑碰撞

滚动哈希把字符串片段映射成数值，预处理后可快速取子串哈希，适合候选筛选。哈希相同只证明摘要相同，不是严格证明原串相同；模数、基数与输入分布会影响碰撞行为。

需要严格正确性时可进一步比较原串，或使用确定性结构。双哈希降低某些碰撞风险，但不能称为数学上绝无碰撞。字符编码也属于输入定义，字节、Unicode 码点和用户看到的字素不是同一层。

<a id="chapter-101-section-05"></a>

### 案例 38：KMP：失配时退到哪个边界

场景与输入：模式 ababaca，文本 abababaca。π 是每个前缀的最长相等真前后缀长度。

手算第 1 步：模式前五个字符 ababa 的 π 依次为 0、0、1、2、3。

手算第 2 步：处理第六个字符 c，候选边界长度 3 对应下一字符 b，不匹配；退到长度 1，仍对应 b，再退到 0，得到 π[5]=0。

手算第 3 步：最终 π=[0,0,1,2,3,0,1]；搜索文本时复用边界，匹配从零基位置 2 开始。

结果与解释：单模式搜索不必在每次失配后让文本指针退回，重叠候选信息已编码在边界链里。

易错点与边界：π 的值是长度而非字符位置；访问 π[j-1] 前必须保证 j>0。

改变条件再想一想：模式 aaa 在文本 aaaaa 中允许重叠时有几个匹配？

自测参考：3 个，起点 0、1、2；报告后退到长度 2，而不是清零。

<a id="chapter-101-section-06"></a>

### 案例 39：多模式：一个位置可以结束多个词

场景与输入：模式 he、she、hers，文本 ushers，零基下标 0…5。

手算第 1 步：文本走到下标 3 的 e 时，后缀 she 对应模式 she，区间 [1,3]。

手算第 2 步：同一位置还有后缀 he，区间 [2,3]；失败链接与输出关系需要保留这个结果。

手算第 3 步：继续读 r、s 后，hers 在 [2,5] 结束；这些结果允许重叠，不能发现一个长词就跳过全部字符。

结果与解释：匹配结果包括 she、he、hers。输出所有结果本身有成本，复杂度说明必须计入输出数量。

易错点与边界：只检查当前 Trie 节点自己的结束标记，可能漏掉失败链上的短模式。

改变条件再想一想：只想判断是否出现过任一模式，还需要存所有匹配位置吗？

自测参考：不需要，可以在发现第一个结果时返回；这改变输出成本，但结构语义仍要正确。

<a id="chapter-102"></a>

## 第 102 讲｜算法进阶 · 动态规划：前驱、区间与状态压缩

领域：算法进阶与面试推理 · 细讲

<a id="chapter-102-section-01"></a>

### LIS：最小结尾表不等于最终路径

最长严格递增子序列可以先用 O(n²) DP 定义：dp[i] 是以 i 结尾的最长长度，枚举更早且值更小的 j。这个版本直接表达子问题，适合先验证状态含义。

更快的 tails[len-1] 保存该长度下目前最小结尾。用 lower bound 替换第一个不小于当前值的位置，得到 O(n log n) 的长度算法。严格递增和非递减的二分边界不同；恢复具体序列需要前驱与末尾位置记录，不能直接返回 tails。

<a id="chapter-102-section-02"></a>

### 带权区间调度：把选择接到兼容前驱

将任务按结束时刻排序。p(i) 是在第 i 项开始前已经结束的最后任务，定义 dp[i] 为前 i 项的最大收益，则比较“不选 i 的 dp[i-1]”与“选 i 的 w[i]+dp[p(i)]”。

前驱可以二分查找，总时间通常 O(n log n)、空间 O(n)。必须先说明结束等于开始算不算冲突。按最早结束贪心可以求某类最多任务数，但收益不同就不能直接沿用这个结论。

<a id="chapter-102-section-03"></a>

### 区间 DP：最后一次划分确定依赖

矩阵链乘的状态可以是连续矩阵 i..j 的最小标量乘法次数。枚举最后一次切分 k，把左右最优值与合并成本相加，再在所有 k 中取最小值。

应按区间长度从小到大填表，保证左右短区间已经求完。n 个矩阵的朴素时间 O(n³)、空间 O(n²)。不同问题可能要求枚举最后合并、最后删除或根节点；套转移式前先说明为什么覆盖所有可能。

<a id="chapter-102-section-04"></a>

### 状态压缩：集合信息怎样进入状态

小规模旅行商问题可用 dp[mask][v]：从固定起点出发，访问 mask 中节点，最后停在 v 的最小代价。转移增加一个未访问节点，最后别忘了加回起点的边。

典型时间 O(n² 2ⁿ)、空间 O(n 2ⁿ)，只适合较小 n；位掩码让集合表示紧凑，不会消除指数状态数。JavaScript 普通按位运算限制在 32 位整数，要先检查规模，必要时使用 BigInt 或其他表示。

<a id="chapter-102-section-05"></a>

### 案例 40：LIS：重复值替换而非延长

场景与输入：输入 [3,1,2,2,5,4]，求最长严格递增子序列长度。

手算第 1 步：读 3 后 tails=[3]；读 1 替换首个不小于 1 的位置，变为 [1]。

手算第 2 步：读 2 延长为 [1,2]；第二个 2 替换同一位置，长度不变，避免把相等算作严格递增。

手算第 3 步：读 5 后为 [1,2,5]，读 4 后为 [1,2,4]，长度为 3。

结果与解释：答案为 3。这里 tails 恰好能形成一个实际序列，但该现象不是所有输入都成立。

易错点与边界：输入 [2,3,1] 的最终 tails=[1,3] 不符合原顺序，不能把它当作恢复出的子序列。

改变条件再想一想：目标改为最长非递减子序列，重复的 2 怎么办？

自测参考：应使用第一个大于当前值的位置更新，使相等值可以延长，当前输入的非递减长度为 4。

<a id="chapter-102-section-06"></a>

### 案例 41：带权调度：前驱让选择可以相加

场景与输入：任务 A=(1,3,5)、B=(2,5,6)、C=(3,6,5)、D=(6,7,4)，三元组是开始、结束、收益。相接边界不冲突。

手算第 1 步：按结束时间顺序 A、B、C、D。只有 A 时最佳收益为 5；加入 B 后为 max(5,6)=6。

手算第 2 步：C 可以接在 A 后，选择它得到 5+5=10，优于不选的 6。

手算第 3 步：D 可以接在 C 后，得到 10+4=14，最终选择 A、C、D。

结果与解释：最大收益 14；兼容前驱索引避免每次重新枚举全部已选组合。

易错点与边界：若结束与开始相等也视为冲突，A 与 C、C 与 D 的兼容关系都会改变。

改变条件再想一想：把 B 收益改为 100，原先的最早结束贪心还最优吗？

自测参考：不再最优。B+D 收益 104，高于 A+C+D 的 14。

<a id="chapter-102-section-07"></a>

### 案例 42：状态压缩：还要记住最后停在哪

场景与输入：四个节点 0…3，有向距离矩阵 \[\[0,2,9,10],[1,0,6,4],[15,7,0,8],[6,3,12,0\]\]。从 0 出发，访问其余各一次后回到 0。

手算第 1 步：状态必须同时包含访问集合和最后节点，因为同一访问集合从不同终点继续，下一条边代价不同。

手算第 2 步：例如路线 0→2→3 的代价为 9+8=17，最后接到 1 再回 0，增加 3+1。

手算第 3 步：这条完整回路为 0→2→3→1→0，总代价 21；枚举另外五种访问顺序可确认没有更低值。

结果与解释：最优回路代价 21；位掩码 DP 以 O(n²2ⁿ) 时间共享子问题，而不是把问题变成多项式规模。

易错点与边界：没有补上回到起点的边，就解成了另一种路径问题；非对称距离不能把反向路线视为相同。

改变条件再想一想：访问完集合后只保留一个最小数，不记录终点够吗？

自测参考：不够，不同终点的后续成本不同，局部较便宜的状态未必能形成全局最优回路。

<a id="chapter-102-section-08"></a>

### 案例 43：区间 DP：乘法顺序改变多少运算

场景与输入：矩阵 A1 为 10×30，A2 为 30×5，A3 为 5×60。只比较标量乘法次数。

手算第 1 步：先算 A1A2，成本 10×30×5=1500，得到 10×5 矩阵。

手算第 2 步：再乘 A3，成本 10×5×60=3000，总计 4500。

手算第 3 步：若先算 A2A3，成本为 9000；再由 A1 左乘，需要 18000，总计 27000。

结果与解释：同一矩阵链的最终形状相同，运算次序可使标量乘法数从 27000 降至 4500。

易错点与边界：此例只优化朴素矩阵乘法的运算次数，不保证在任意硬件与实现上实际耗时也正好缩为六分之一。

改变条件再想一想：只有一个矩阵时，状态的基础成本是多少？

自测参考：0，因为没有矩阵乘法需要执行。

## 第 103 讲｜算法进阶 · 贪心证明与二分答案

领域：算法进阶与面试推理 · 细讲

<a id="chapter-103-section-01"></a>

### 交换论证：好直觉需要可以替换的最优解

贪心的解释应说明某个最优解可以怎样替换成以当前选择开头的同样好解。对无权、非重叠区间的最多选择数，优先结束最早的任务，为后续保留最多时间，可以用交换第一个任务说明安全性。

一旦任务有不同收益、机器有多个资源约束或允许抢占方式变化，原证明可能不再成立。面试时给出反例，比只背一个“常用贪心规则”更能说明你理解目标和约束。

<a id="chapter-103-section-02"></a>

### 二分答案：单调的是可行性

不是只有有序数组才能二分。给定一个候选上限 B，若可以判断是否存在满足它的方案，而且答案随 B 单调变化，就可以查找从不可行到可行的边界。

例如非负任务按原顺序分给至多 k 组，最小化最大组和。下界为最大单项，上界为全部总和；B 越大只会放宽限制。二分循环应维护明确边界，而不是靠遇到一个可行值就立即返回。

<a id="chapter-103-section-03"></a>

### 可行性检查：分组贪心的适用前提

给定上限，从左到右尽可能把下一项放进当前组，放不下才开启新组。非负数使“越往后加不会减少当前组和”成立，因此这个检查可以计算所需最少组数。

如果允许负数，当前超限可能被之后的负项抵消，提前切组的论证失效。若要求恰好 k 个非空组，非负且 k 不超过 n 时，可把较大组继续拆分而不提高最大和；其他约束要重新论证。

<a id="chapter-103-section-04"></a>

### 数值搜索与复杂度的表达

整数答案若区间宽度为 U，一次检查 O(n)，总时间通常 O(n log U)，额外空间可以 O(1)。这和对 n 个已排序元素做 O(log n) 查找不是同一个复杂度参数。

浮点答案需要误差或迭代次数约定；中点计算要考虑溢出，终止条件要与区间约定一致。不要把固定精度小数搜索直接写成 left=mid+1，也不要忽略输入范围决定的整数精度。

<a id="chapter-103-section-05"></a>

### 案例 44：二分答案：先检查候选上限

场景与输入：非负任务 [7,2,5,10,8]，保持顺序，分成至多 2 个非空连续组，最小化最大组和。

手算第 1 步：答案至少是最大单项 10，至多是全部总和 32。

手算第 2 步：候选上限 17：先放 [7,2,5] 和为 14，再放 [10]，最后的 8 需要第三组，所以不可行。

手算第 3 步：候选上限 18：分为 [7,2,5] 与 [10,8]，两组足够。二分缩小最早可行上限，得到 18。

结果与解释：最优最大组和为 18，划分点在 5 与 10 之间。单次检查 O(n)，整数搜索约 O(n log U)。

易错点与边界：贪心检查依赖非负数；如果存在负数，超限后还可能被后续负数抵消，不能原样使用。

改变条件再想一想：最多一组时，答案是多少？

自测参考：32，全部任务必须留在同一个组。

<a id="chapter-103-section-06"></a>

### 案例 45：贪心反例：最多任务与最高收益

场景与输入：仍使用 A=(1,3,5)、B=(2,5,100)、C=(3,6,5)、D=(6,7,4)，相接不冲突。

手算第 1 步：若目标是数量最多，最早结束规则选 A、C、D，共 3 项。

手算第 2 步：若目标是收益最大，同样的选择只有 14；选择 B、D 收益为 104。

手算第 3 步：问题描述只改了优化目标，安全选择的证明就需要重做，可转成带权区间 DP。

结果与解释：“某规则常见”不等于它适用于所有看起来相似的调度题。

易错点与边界：不要一看到区间就固定按开始或结束排序后贪心；需要先明确目标、兼容条件和资源限制。

改变条件再想一想：若全部收益都为 1，两种目标还冲突吗？

自测参考：不冲突，最大收益等同于最大数量，可以恢复无权情形的结论。

<a id="chapter-104"></a>

## 第 104 讲｜算法进阶 · 随机与流式：采样、过滤与误差

领域：算法进阶与面试推理 · 细讲

<a id="chapter-104-section-01"></a>

### 蓄水池采样：不知道总长度也能等概率

只保留一个样本时，第 i 个元素以 1/i 的概率替换当前样本。第 j 个元素最终留下的概率为“当时选中”乘“之后一直没被替换”，各因子相消后为 1/n。

保留 k 个样本可先装满，再对第 i 项生成均匀的随机下标，落在前 k 个位置时替换。时间 O(n)，空间 O(k)；随机源、索引区间与去重语义都要说明。同值的不同记录默认是不同采样单位。

<a id="chapter-104-section-02"></a>

### 随机化快速选择：期望不等于最坏

快速选择只继续处理包含目标排名的一侧，不必把两边都排好。随机选主元可避免固定输入持续触发某种确定性坏划分，常见分析给出期望线性时间。

最坏情况下仍可能出现 O(n²)；需要最坏线性保证时，应讨论确定性选择等其他策略。遇到很多重复值时，三路划分能集中等于主元的区间，减少不必要工作。

<a id="chapter-104-section-03"></a>

### Bloom filter：肯定不在与可能在

Bloom filter 用多个哈希位置记录位。查询发现任一位为 0，可以判定没有插入过；全为 1 只能说可能存在，因为不同元素可能共同设置这些位。

在标准只插入、哈希规则一致且无损坏的使用条件下，没有假阴性，允许假阳性。位数、哈希数、预计容量影响误判；直接清除某元素的位会破坏其他元素的记录，删除需要计数等其他结构。

<a id="chapter-104-section-04"></a>

### 近似统计：先说清误差与资源

流式频次、去重和分位数可以用不同摘要；选择前先说明要估计什么、是否需要合并、允许何种误差以及如何处理重复。Bloom 的成员过滤与基数估计不是同一个目标。

经验“看起来差不多”不是误差保证。对随机近似结果，应区分偏差、方差和失败概率，并保留小规模精确计算作对照。需要精确业务约束时，摘要可以做前置筛选，但通常还要查真实记录。

<a id="chapter-104-section-05"></a>

### 案例 46：蓄水池：每个元素最后都有三分之一

场景与输入：流依次到来 A、B、C，只保留一个样本，每个元素按其位置执行替换概率。

手算第 1 步：A 首先进入；B 以 1/2 概率替换 A。

手算第 2 步：C 以 1/3 概率替换当前样本；A 最终保留的概率为 1×1/2×2/3=1/3。

手算第 3 步：B 最终保留的概率为 1/2×2/3=1/3；C 最终保留的概率就是 1/3。

结果与解释：三个位置等概率被留下，无需事先知道流最终长度。

易错点与边界：每次都以 1/2 替换会偏向较晚元素；均匀整数随机区间的端点错误也会改变概率。

改变条件再想一想：A、A、B 三条记录，最后取到值 A 的概率是多少？

自测参考：2/3。这里按记录位置均匀采样，两个 A 是两个不同位置，并非先按取值去重。

<a id="chapter-104-section-06"></a>

### 案例 47：Bloom：两个已见元素拼出一个误报

场景与输入：8 位全零位图，两个哈希位置。A 对应 [1,4]，B 对应 [4,6]，未插入的 C 对应 [1,6]。

手算第 1 步：插入 A，将位 1、4 设为 1；插入 B，将位 4、6 设为 1。

手算第 2 步：查询 C 的两个位置都为 1，因此返回“可能存在”，但 C 从未插入，这是一个假阳性。

手算第 3 步：若为了删除 A 直接清零位 4，则 B 的查询会遇到 0，产生错误的缺失判断。

结果与解释：共享位带来紧凑存储，也带来误报和普通删除的限制；可再查精确记录确认。

易错点与边界：这个固定的小位图只展示机制，不能用它宣称某个生产系统的误判率。

改变条件再想一想：查询 D 的位置为 [0,6]，能确定什么？

自测参考：因为位 0 仍为 0，在标准只插入且哈希一致的条件下，可确定 D 未插入。

## 第 105 讲｜算法进阶 · 面试中的正确性、摊还分析与测试

领域：算法进阶与面试推理 · 细讲

<a id="chapter-105-section-01"></a>

### 四句话建立求解契约

先复述输入与输出，再问范围和约束，然后给出一个手算例子，最后说明什么情况下当前办法不适用。整数、重复值、空输入、有向边、负权等细节，往往决定算法是否成立。

把正确性依据说成可检查的不变式。例如窗口中没有重复字符、栈中仍是未解决且按温度有序的候选、堆中保留已见数据的前 k 名。变量名不替代状态定义，循环写出来也不等于证明。

<a id="chapter-105-section-02"></a>

### 最坏、期望与摊还分别回答什么

最坏分析关注允许输入中最昂贵的情况；期望分析必须交代随机性来自算法还是输入模型；摊还分析把一串操作的总代价分配到每次操作，不要求随机输入。

动态数组一次扩容可能复制很多元素，但按倍数增长时，前面复制量形成几何级数，n 次追加总成本 O(n)，因此摊还 O(1)。固定只增加一个容量则可能累积为 O(n²)，不能只看追加语句本身。

<a id="chapter-105-section-03"></a>

### 实现细节会改变复杂度

算法中写“出队”并不自动得到常数时间。如果语言容器用移动所有剩余元素的方式删除头部，就可能把理论线性遍历变慢；可以使用头指针或双端队列。

同样需要检查字符串切片、数组复制、递归深度和整数精度。输出所有排列本身就可能占阶乘级规模；只说辅助栈 O(n) 而完全不提输出，会让资源说明失真。

<a id="chapter-105-section-04"></a>

### 用小规模枚举做独立对照

对优化算法，可在很小输入上写容易相信的穷举作为参照：枚举所有区间验证前缀计数，枚举所有子集验证背包，枚举所有排列核对小规模旅行商。参照实现应采用不同思路，减少把同一错误复制两次的风险。

测试应覆盖空、单元素、全相等、重复边、不可达、正好在边界、溢出范围等适用情形；有前提的算法也应测试拒绝或明确说明不支持的输入。通过例子验证可以发现错误，但不取代一般正确性论证。

<a id="chapter-105-section-05"></a>

### 案例 48：动态数组：昂贵扩容如何摊还

场景与输入：容量初始为 1，满时扩为 2 倍；追加 8 个元素，忽略分配器额外开销。

手算第 1 步：扩到容量 2、4、8 时，分别复制已有的 1、2、4 个元素，总复制量为 7。

手算第 2 步：八次写入加七次复制，共 15 次单位工作。某一次追加可能很贵，但整段工作仍与 8 成正比。

手算第 3 步：若追加第 9 个，需要扩到 16 再复制 8 个；此前复制总量变为 15，总单位工作 24，仍小于 3×9。

结果与解释：按倍数增长时，几何级数控制 n 次追加总成本 O(n)，所以追加的摊还成本 O(1)。

易错点与边界：摊还结论不是每次最坏 O(1)；如果每次只扩一格，复制量会变成 1+2+…+(n-1)。

改变条件再想一想：扩容到新数组时，旧内存可立即忽略吗？

自测参考：不能，复制期间可能同时存在新旧数组，峰值内存和释放策略需单独考虑。
